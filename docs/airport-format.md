# Airport data format (v1)

Reference for anyone producing or curating airport files (PLAN 1.5 JFK import, 1.6 LGA). The
types in `src/airport/types.ts` are the authority; this page is the overview.

| File | What |
|---|---|
| `data/airports/<ID>.json` | Base data, normally generated by an importer (OSM for JFK/LGA). |
| `data/airports/<ID>.overrides.json` | Optional hand-curated changes on top of the base. |
| `data/airports/TEST.json` | Synthetic airport that uses every feature; the sim's tests run on it. |
| `src/airport/load.ts` | `loadAirport(base, overrides?)`: merge + shape check. Pure; you pass parsed JSON. |
| `src/airport/validate.ts` | `validateAirport(airport)`: meaning checks → `{ ok, errors, warnings }`. |
| `src/airport/graph.ts` | `indexAirport` (lookups, adjacency), edge lengths and polylines. |
| `src/airport/geo.ts` | `toLocal` / `toLatLon`: the exact projection of the local frame. |

Check a file with `npm run validate-airport -- <ID>` (exit 0 = valid; warnings allowed).

## Frame, units, names

- Positions are **meters**, `x` east and `y` north of `reference` (WGS84 lat/lon stored in the
  file). Project with `geo.ts`'s `toLocal` so every tool agrees; rounding to 0.1 m is plenty.
- Headings are degrees true, clockwise from north.
- **Names are strings**: `"A"`, `"KE"`, `"C1"`, ramp lane `"7"`, gate `"B22"`.
- **Runway designators are FAA style without a leading zero**: `"4L"`, `"31R"`, `"9"`, never
  `"04L"`. The terse parser (`src/sim/terse.ts`) normalizes to the same form, so commands and
  data match exactly. Runway ids are conventionally `"<low>/<high>"`: `"4L/22R"`, `"13R/31L"`.
- Every item has an `id`, unique in its collection, opaque and stable. Overrides and other
  items refer to ids, so keep importer ids deterministic across re-imports (e.g. derived from
  OSM element ids) or the overrides file breaks, loudly.
- Optional fields are omitted, never `null`. Unknown fields are rejected (typos fail).

## The collections

The movement surface is an undirected graph. Everything else points into it.

| Collection | One item is | Key fields / rules |
|---|---|---|
| `nodes` | a graph point | `x`, `y` |
| `edges` | one segment between two nodes | `kind`: `runway` (tower), `taxiway` (player's movement area), `rampLane` (ramp's non-movement area, incl. gate lead-ins). `name` (taxiway/lane name; not on runway edges). `runway` (required on runway edges). `points` (interior shape points), `widthM`, `closed: { reason }`. A taxiway = the taxiway edges sharing a name. |
| `runways` | a runway | `ends: [end, end]`, each `{ designator, node, displacedThresholdM? }`, where `node` is the pavement end that direction starts from. Its runway edges must form one path from `ends[0].node` to `ends[1].node`. Intersecting runways share the crossing node. `widthM`, `towerPosition?`. |
| `runwayExits` | a way off a runway for one landing direction | `runwayEnd`, `taxiway` (spoken name, must equal the edge's name), `node` (on the centerline), `edge` (first edge off). Order along the runway comes from geometry. |
| `holdShorts` | a hold line at a node | `kind`: `runway`, `ils`, `lahso`, `intermediate`. `runways`: the protected runway(s), one or more (several at intersections); empty only for `intermediate`. Directional: applies at `node` to traffic about to enter `towardEdge`. |
| `rampHandoffs` | a ramp ↔ ground handoff point | `name` (check-in name: `"KF"`, `"HB"`, `"TA"`, `"7"`), `node` (where a rampLane edge meets a taxiway edge), `use`: `departures` (ramp edge, where departures check in), `arrivals` (ramp entrance), `both`. `terminals?` it serves. |
| `terminals` | a terminal | `name`, `airlines` (ICAO designators: `"DAL"`). |
| `gates` | a parking position | `name`, `terminal`, `node` (touched only by rampLane edges), `headingDeg?`, `airlines?` (subset of the terminal's). |
| `holdingAreas` | a pad or the penalty box | `kind`: `pad` or `penaltyBox`. `spots`: nodes where one aircraft each waits. `outline?`. |
| `departureLines` | the queue for one runway end | `runwayEnd`, `holdShort` (the `runway` hold at the front, where the player hands off to tower), `edges` (back → front, one path ending at that hold's node), `exits` (back → front, each `{ taxiway, node, edge }`; ≥ 1; never a runway or toward one). |
| `configurations` | a runway configuration | `runways: [{ end, roles: ["arrivals" \| "departures", …], arrivalExits? }]`, one entry per runway. JFK's 31s: `31L` with both roles, `31R` arrivals. |
| `towerPositions` | a tower position | `name`, `frequency` (`"123.9"`). Runways name their position (JFK splits tower by runway pair; LGA has one). |
| `areas` | display-only polygon | `kind`: `apron`, `terminalBuilding` (+ `terminal`), `building`. `outline` ≥ 3 points. |

All thirteen collection keys must be present in the base file (an empty array is fine).

**Closures** are data: `"closed": { "reason": "…" }` on an edge. A closed edge is still drawn,
but nothing may route over it, and the validator's reachability ignores it. Close the exact
segments, splitting edges at the closure's ends if needed.

**Turn restrictions** (e.g. JFK "Twy NB clsd to SB turns at Twy A") are deferred. The way to
add them later is a new collection such as `turnRestrictions: [{ id, fromEdge, viaNode,
toEdge }]`. It's an additive format change, possible because edges and nodes have stable ids.

## Overrides semantics

```json
{
  "formatVersion": 1,
  "airport": "KJFK",
  "description": "Hand-curated: names, closures, pads, lines, configurations, terminals.",
  "set": { "name": "John F. Kennedy International" },
  "edges": {
    "patch": [
      { "id": "w123-4", "name": "A7" },
      { "id": "w456-2", "closed": { "reason": "Chart Supplement: Twy Z btn Rwy 04L and 22R and Twy Y clsd UFN" } }
    ]
  },
  "holdingAreas": { "add": [{ "id": "padK", "name": "Kilo pad", "kind": "pad", "spots": ["n9"] }] },
  "gates": { "remove": ["osm-gate-17"] }
}
```

- `airport` must equal the base `id`; `formatVersion` must be 1.
- `set` replaces top-level `name`, `reference` or `source`; `null` removes `source`.
- Per collection: **`add`** (new ids only, appended in order), **`replace`** (whole item, same
  position), **`patch`** (shallow: listed fields replace the base's, arrays and objects whole;
  `null` removes a field; `id` only selects), **`remove`** (by id).
- `replace`, `patch` and `remove` ids must exist **in the base file**, and `add` ids must not.
  An id may appear in only one operation per collection, so operation order never matters.
- Nothing cascades: removing a node that an edge still uses is a validation error.
- Every problem is collected and thrown together as `AirportLoadError.issues`, with paths like
  `overrides.edges.patch[3]` or `edges[58] ("aK-wpS").kind`.
- Merging happens before the shape check, so the base may be incomplete (e.g. gates without a
  `terminal`) as long as the merged result is complete.

## What the validator checks

**Errors** (the airport is unusable until fixed), by area:
- **References:** duplicate ids or runway-end designators; every reference resolves.
- **Edges:** no self-loops; `runway` set on exactly the runway edges.
- **Runways:** FAA-style designators; centerline is one path end to end; displaced threshold
  shorter than the runway.
- **Runway exits:** the exit node is on the runway, its edge is a non-runway edge touching that
  node, the edge's name matches, and the edge is open.
- **Hold-shorts:** `runway`/`ils`/`lahso` holds name ≥ 1 runway (and intermediate holds name
  none); `towardEdge` touches the node; no hold sits on the centerline of a runway it protects.
- **Network:** all open edges form one connected network (`disconnected-network`).
- **Runway entries:** taxiing from any ramp handoff or holding spot can't reach a runway without
  passing one of that runway's `runway` holds in the protected direction
  (`runway-entry-unprotected`).
- **Ramp:** each ramp handoff sits on a ramp-lane/taxiway boundary and is connected. Gates touch
  only ramp lanes. Every gate is reachable over open ramp lanes from a ramp entrance serving its
  terminal, and can reach a ramp edge (`gate-unreachable`). Gate names are unique per terminal,
  and gate airlines are a subset of the terminal's.
- **Holding areas:** each has spots, and the spots are connected and not on a runway.
- **Departure lines:** each has ≥ 1 exit. Its edges form one open, non-runway path ending at a
  `runway` hold protecting its runway. Exits are on the line, in order, and leave by an open
  taxiway with a matching name, not by a runway or toward one.
- **Configurations:** they use known ends, each runway once, with valid roles. Arrival ends
  have exits; `arrivalExits` belong to that end.
- **Display:** tower frequencies look like MHz; outlines have ≥ 3 points.

**Warnings** (allowed, but look):
- Holds with no node of their runway within 500 m beyond them.
- Undeclared ramp/ground boundary nodes.
- Terminals with no gates.
- No pad, no penalty box or no configuration.
- A departure end with no departure line; a configuration with only arrivals or only
  departures.
- Non-reciprocal designators; zero-length edges; nodes with no edges.
- Positions more than 20 km from the reference point (a projection mistake).

Codes are the `IssueCode` union in `validate.ts`; tests assert on them.

## Notes for the JFK/LGA import (1.5, 1.6)

- Split OSM ways at every shared node and at every hold position, so holds and exits sit on
  graph nodes. Give each hold the edge toward its runway as `towardEdge`.
- OSM `holding_position:type` maps roughly to `kind` (`runway`, `ILS` → `ils`, `LAHSO` → `lahso`,
  `intermediate`). Which runway a hold protects isn't in OSM: derive it from geometry, then check.
  The `hold-short-far-from-runway` warning and `runway-entry-unprotected` error catch mistakes.
- OSM `taxilane` is only a hint for `rampLane`. Ramp handoffs and their check-in names are
  curated (research doc §8.9).
- Put the OSM licence in `source.license` ("Data © OpenStreetMap contributors, ODbL 1.0").
